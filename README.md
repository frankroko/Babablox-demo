# Babablox (Vite + React + Tailwind CSS v4)

A Thai-language e-commerce demo for buying/selling game accounts and in-game items. The project has been migrated from static HTML/CSS/JS to Vite + React with Tailwind CSS v4 and SweetAlert2.

## Tech Stack

- Vite 8
- React 19
- React Router 7
- Tailwind CSS v4
- SweetAlert2
- Sharp (image optimization script)
- Express 5
- MongoDB with Mongoose 9
- JWT + bcrypt 6 authentication
- pnpm 10 package management

## Project Structure

```text
babablox-demo/
  index.html            # Vite entry HTML
  package.json          # Scripts + dependencies
  vite.config.js        # Vite config (React + Tailwind v4 plugin)
  public/

    App.jsx             # App shell + routes

    pages/              # Route pages (Home, Products, Cart, Orders, Auth)

    app.js              # Express app, middleware, routes, static fallback
    index.js            # API server entry
    routes/             # Auth, products, cart, orders, admin
    models/             # Mongoose models
```

## Getting Started

Prerequisites: Node.js 20.19+ (or 22.12+) and pnpm 10+ recommended.

Install dependencies:

```bash
pnpm install
```

Run the dev server:

```bash
pnpm dev
```

For full-stack local development, run the API server in another terminal:

```bash
pnpm dev:server
```

By default the frontend calls same-origin `/api/...` paths. Vite proxies those requests to `VITE_API_PROXY_TARGET`, which defaults to `http://localhost:3001`.

Create a production build:

```bash
pnpm build
```

Preview the production build locally:

```bash
pnpm preview
```

## Backend Setup

Create a `.env` file using `.env.example` as a starting point.

Required environment variables:
- `MONGODB_URI`
- `JWT_SECRET`

Optional environment variables:
- `PORT`
- `MONGODB_DBNAME`
- `JWT_EXPIRES_IN`
- `CORS_ORIGIN`
- `ADMIN_EMAIL`
- `JWT_COOKIE`
- `COOKIE_SECURE`
- `VITE_API_URL` (optional frontend override; leave blank for same-origin `/api`)
- `VITE_API_PROXY_TARGET` (Vite dev proxy target, usually `http://localhost:3001`)

Run the API server:

```bash
pnpm dev:server
```

Seed the product catalog (optional):

```bash
pnpm seed:products
```

## API Overview

Auth:
- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me`
- `POST /api/auth/logout`

Products:
- `GET /api/products`
- `GET /api/products/:id`
- `POST /api/products` (admin)
- `PATCH /api/products/:id` (admin)
- `DELETE /api/products/:id` (admin)

Cart:
- `GET /api/cart`
- `POST /api/cart/items`
- `PATCH /api/cart/items/:itemId`
- `DELETE /api/cart/items/:itemId`
- `DELETE /api/cart`

Orders:
- `POST /api/orders`
- `GET /api/orders`
- `GET /api/orders/:id`
- `PATCH /api/orders/:id/status` (admin)

Admin:
- `GET /api/admin/users`
- `PATCH /api/admin/users/:id`
- `DELETE /api/admin/users/:id`
- `GET /api/admin/orders`

## Image Optimization

Optimize images into WebP files under `public/assets-optimized`:

```bash
pnpm optimize:images
```

Notes:
- The seed data currently references images from `public/assets`.
- If you add new images to `public/assets`, run the optimizer again.

## Key Behavior

- Auth uses JWT stored in `localStorage`; cart and orders are loaded from the API.
- Orders route (`/orders`) requires login.
- Admin routes use a separate `adminAuthToken` localStorage key.
- Admin accounts can manage products, users, and orders, but cannot use carts or place orders.
- Order status values are `pending`, `paid`, `fulfilled`, and `cancelled`.
- The mobile navbar uses a burger menu with an animated close state.
- The frontend now uses the backend APIs for auth, cart, and orders.
